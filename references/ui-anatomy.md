# UI anatomy

The original Eden Forge page uses an editorial hierarchy rather than a dashboard shell. A narrow header leads to a split hero, then full-width explanation sections. Its quiet palette leaves typography and the active layer as the focal points.

| Role | Original treatment |
| --- | --- |
| Background | `#101b1a`, deep forest green |
| Panel / rules | `#172522` / `#34433b` |
| Main text / supporting text | `#eef0e4` / `#a8b5a6` |
| Active accent | `#cbe8ae`, pale sage |
| Headlines | Georgia/Times serif; 56–86 px desktop hero, tight tracking, italic accent |
| Body | Native system sans serif, restrained measure and generous line height |
| Figure labels | 8–11 px monospace, uppercase, small tracking |
| Desktop frame | Maximum 1320 px content, 56 px side margins, 84 px header |
| Hero | Two near-equal columns; approximately 710 px minimum height |
| Figure | Thin border, quiet radial green wash, dot field and framed caption |
| Sections | Thin dividers, 60–95 px vertical spacing, large serif headings |
| Selected control | Solid pale-sage fill with dark text; inactive controls remain quiet |

The original full page continues into recorded lab results, a five-surface explorer, a pale seed-model specification band, an experiment-plan form, expandable roadmap rows and a source list. Those are project content, not mandatory sections in another site's design. The starter retains the hero, accessible layer explorer and an explanation band.

Keep the canvas in a fixed-height responsive frame so its geometry remains legible. At 760 px and below, stack the hero, reduce the type scale and turn the controls into multiple rows. Labels should be short; detail belongs in the selected-component panel.

The visual figure represents software and hardware domains using a common board-shaped grammar. A diagram layer is not a claim that a software harness is a physical chip. Keep that distinction explicit in explanatory copy. Do not describe the moving dots as measured data.
